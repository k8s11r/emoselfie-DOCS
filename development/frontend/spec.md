`Design Delta.md`는 PRD v1.1을 참조하지만 현재 PRD 헤더는 v1.0이다. 현재 디자인에는 이미 감정 7종, `cursorId`, 리액션 토글, 신규 오류·권한 화면이 반영되어 있다. 델타 문서의 “아직 수정하지 않았다”는 서술을 현재 파일 상태로 간주하지 않는다. 델타의 `Happiness` 등 대문자 엔진 라벨 대신 PRD·BE의 소문자 라벨을 사용한다.

### 1.3 기존 백엔드 결정의 화면 반영

- D-1: 결과용 재인코딩 JPEG를 Redis 임시 캐시에 두고 열람자별 서명 URL로 조회한다. 종료 시 파기한다. 사용자 고지 문구는 Q-1에서 확정한다.
- D-2: 얼굴 미검출은 `0.0점`과 “얼굴을 찾지 못했어요”, 포인트는 서버가 내려준 30을 표시한다. 순위가 2위여도 FE에서 70으로 바꾸지 않는다. 엔진 실패는 `판정 불가`, 순위는 `—`, 보정 포인트는 서버 값을 표시한다.
- D-3: FE·API·소켓·미디어는 동일 오리진. `/api`, `/socket.io`, `/media`를 사용한다.
- D-4: 미제출 안내는 채점 중 안내 → 서버 시각이 도착하면 다음 라운드 카운트다운의 2단계다.
- D-5: 무효 라운드를 FE에서 재실행하지 않는다. 다음 라운드 또는 중단 결과로 이동한다.
- D-6: 연결 상태와 참여 자격은 별개다. 끊겼다고 즉시 정원에서 빼거나 게임을 종료하지 않는다. 서버는 60초 유예 정책을 가진다.
- D-7: 중복 닉네임을 허용한다. 접미사를 자동으로 붙이지 않고 participantId·색상·“나” 표시로 구분한다.
- D-8: 서버의 저장소 전환은 FE가 알 필요 없다. 받은 누적 포인트를 대입하며 중복 이벤트마다 더하지 않는다.

## 3. 화면 진입과 상태 모델

### 3.1 라우팅

| 경로 | 책임 |
|---|---|
| `/` | 랜딩·방 설정·방 만들기 |
| `/r/:slug` | 세션 확인 → 입장 절차 또는 기존 상태 복원 → 서버 screen에 맞는 방 화면 |
| 그 외 | 링크 오류 안내와 랜딩 이동 |

라운드 결과를 별도 공개 URL로 만들지 않는다. 닉네임·권한·게임 화면은 RoomEntry/RoomScreenResolver가 분기한다. URL·브라우저 뒤로 가기만으로 과거 라운드에 접근할 수 없으며, 새로고침 시 `/state`가 현재 화면을 결정한다. 화면 전환은 같은 방 경로 내에서 수행해 라운드마다 history를 쌓지 않는다.

### 3.2 상태의 소유권

| 계층 | 상태 |
|---|---|
| 서버 권위 | room, me, participants, round, submission 결과, rank, totalPoints, reaction counts, skip 현황, 화면 접근권한, 마감 시각 |
| Zustand | 위 서버 데이터의 최신 클라이언트 복제본, connection·restoring 상태, 현재 선택 participantId |
| TanStack Query | me 초기 조회, 입장·방 생성·설정·닉네임 API, snapshot 요청 상태 |
| 화면 로컬 | 폼 입력 초안, 설정 시트 열림, 복사 토스트, 포커스 |
| Camera/Media 서비스 | MediaStream, video 참조, 캡처 Blob, Object URL, 요청 취소·해제 핸들 |

HTTP snapshot을 검증한 뒤 store에 한 번에 적용한다. Query cache와 store를 독립된 게임 상태 원본으로 사용하지 않는다. 소켓 이벤트는 공통 핸들러에서만 적용하며 화면마다 소켓을 만들지 않는다. 미디어 객체는 persist·devtools 직렬화·로그 대상에서 제외한다.

```ts
// FE 내부 모델. 실제 DTO는 BE 계약을 검증·변환해 사용한다.
type Connection = 'connecting' | 'connected' | 'reconnecting'
  | 'restoring' | 'offline' | 'superseded';
type CameraPermission = 'unknown' | 'prompt' | 'granted' | 'denied' | 'no_device';
type CameraPhase = 'idle' | 'starting' | 'live' | 'review'
  | 'interrupted' | 'error';
type LocalSubmission = 'idle' | 'encoding' | 'uploading'
  | 'checking' | 'accepted' | 'retryable_error' | 'rejected';
type ResultStatus = 'processing' | 'submitted' | 'no_face' | 'failed' | 'missed';
```

`unknown`은 조회 전/조회 불가능한 내부 상태이며 사용자에게 “거부됨”으로 표시하지 않는다. `no_face`와 `failed`는 서버 결과, 카메라 `error`는 기기 상태로 분리한다.

### 3.3 화면 선택 순서

1. `session:superseded` 수신 시 기존 연결의 자동 재접속을 중지하고 세션 종료 안내를 표시한다.
2. 초기 진입은 `GET /api/me`로 세션을 준비한다. 방 소유 힌트만으로 권한을 결정하지 않는다.
3. 기존 참여자 복원을 먼저 시도한다. 이미 finished인 참여자가 일반 입장 조회의 410 때문에 결과 복원을 잃지 않도록 `/state` 경로를 먼저 사용한다.
4. 신규 입장은 최소 방 조회·닉네임·카메라 준비를 거쳐 참여자 API를 호출한다. 정원은 카메라 준비 후 입장 시 서버가 다시 판정한다.
5. 권한 미확인·거부 화면에서는 저장된 방 데이터도 화면에 노출하지 않는다. 권한 철회 시 미디어·결과 캐시를 제거한다.
6. 참여가 확인되면 서버 snapshot의 `game.screen`으로 대기실·카운트다운·촬영·결과·미제출·최종 화면을 선택한다. 초기 waiting snapshot의 화면 필드 위치는 B-1 계약에서 정규화한다.
7. 서버가 알려준 `countdownEndsAtMs` 경과에 따른 촬영 화면 전환만 로컬 예약한다. 라운드 종료·미제출·득점은 로컬 타이머로 확정하지 않는다.

## 4. 화면별 구현 명세

### 4.1 랜딩 — Landing

근거: RO-01~03·17, RD-01·04, PM-16, ID-08. 참조: `Landing.dc.html`.

- 로고, 게임 설명, 2~12명 안내, 라운드 수/제한시간 칩, 카메라 필수 안내, 방 만들기를 배치한다.
- 설정 칩은 단일 선택 라디오 그룹. 기본값 5라운드·20초. 요청 중 중복 방 생성 버튼 입력을 잠근다.
- `POST /api/rooms` 성공 후 해당 slug의 입장 흐름으로 이동한다. `existing:true`는 “이미 만든 방으로 이동했어요” 토스트를 표시한다. 기존 방이 playing이면 실제 현재 상태를 복원하며 대기실로 강제 이동하지 않는다.
- 최초 접속에 익명 참여 식별을 위한 쿠키 사용 사실을 짧게 안내한다. 쿠키 UUID를 JavaScript에서 읽거나 별도로 생성하지 않는다.
- 시안의 예상 게임 시간은 사용자 대기·채점·감상 시간에 따라 달라진다. 검증되지 않은 고정 예상 분 표기는 생략한다.

### 4.2 닉네임 — NicknameSetup (전용 시안 없음)

근거: ID-04, RO-05, BE D-7.

- 공통 카드 안에 제목 “어떤 이름으로 참여할까요?”, label이 있는 입력, 글자 수, 다음 버튼을 둔다.
- `GET /api/me.nickname`을 기본값으로 채운다. 입력 중 사용자의 초안을 늦은 응답으로 덮어쓰지 않는다.
- 2~10자. 중복 허용. 닉네임은 일반 텍스트로 렌더링한다. 입력 조합 중인 한글을 잘라내지 않는다.
- 공백 제거·Unicode 길이·허용 문자 규칙은 B-8에서 BE와 맞춘다. 프론트엔드만의 금칙어·자동 접미사 정책을 추가하지 않는다.
- 서버 검증 실패는 입력 아래 표시하고 입력을 보존한다. 신규 사용자는 닉네임 저장 후 카메라 사전 안내로 이동한다.
- 프로필 색상은 입장 응답의 colorTag를 사용한다. 시안용 랜덤 색을 실제 참여자 ID처럼 사용하지 않는다.

### 4.3 카메라 사전 안내 — CameraIntro

근거: PM-01·02·04·06·07·12·16. 참조: `CameraIntro.dc.html`.

- 목적·사진 처리 고지(Q-1)·제출 전 본인만 확인 가능함·카메라 켜기를 표시한다.
- 권한 획득 전 방 설정·인원·닉네임 목록·진행 정보를 표시하지 않는다. 시안의 `roomSummary`는 제거한다.
- 카메라 켜기 탭 후 실제 video 스트림 획득이 성공하면 모든 track을 중지하고 참여자 등록을 호출한다. 등록 완료 후 소켓 연결·snapshot 동기화를 한다.
- 이미 granted임을 확인할 수 있는 재접속은 추가 프롬프트 없이 준비 상태를 확인·복원한다. 상태 불명/조회 미지원은 Q-5 결정에 따른다.
- 요청 진행 중 버튼을 잠그며 브라우저 권한 팝업의 응답을 기다리고 있다는 안내를 표시한다. 사용자가 늦게 허용했는데 화면은 떠난 경우 획득한 스트림을 즉시 정지한다.

### 4.4 참여 불가 — CameraBlocked

근거: PM-05·07~09·11·13. 참조: `CameraBlocked.dc.html`.

| 원인 | 문구·액션 |
|---|---|
| 권한 거부 | 카메라 없이는 참여할 수 없어요 / 설정 방법 보기 / 설정 변경 후 상태 확인 |
| 카메라 없음 | 카메라를 찾을 수 없어요 / 카메라가 있는 기기에서 링크 열기 안내 |
| 장치 사용 불가·점유 가능성 | 카메라를 켤 수 없어요 / 다른 앱 종료 안내 / 다시 시도 |
| 지원하지 않는 환경 | 이 환경에서는 카메라를 사용할 수 없어요 / 지원 브라우저에서 열기 안내 |

점유 오류의 원인을 “다른 앱이 사용 중”이라고 단정하지 않는다. 설정 안내 시트는 iOS Safari·Android Chrome을 선택할 수 있게 한다. 시안의 주소창 아이콘과 설정 경로는 예시이며 실제 지원 버전에서 확인한 문구로 출시한다. 설정을 FE가 직접 변경할 수 있는 것처럼 표현하지 않는다.

거부 상태의 “다시 시도”는 강제 프롬프트 재노출을 약속하지 않으며 변경된 권한 상태를 확인하는 역할이다. 권한이 회복되면 같은 slug로 입장/복원을 진행한다. 누적 포인트는 서버 복원값을 사용한다.

### 4.5 대기실 — Lobby

근거: RO-04·06~14·17, PM-10. 참조: `Lobby.dc.html`.

- 설정 요약, 초대 링크 복사, 정원 대비 인원, 참여자 목록, 현재 방장·나 표시를 둔다.
- 연결 배지는 `연결됨` / `연결 끊김` 등 실제 connectionStatus를 사용한다. 시안의 준비 완료·입장 중을 카메라 준비율로 해석하지 않는다.
- 서버가 반환한 초대 URL 또는 현재 오리진과 검증된 slug로 링크를 만든다. 시안의 6자 slug·하드코딩 도메인을 쓰지 않는다.
- 복사 완료 토스트는 Clipboard 쓰기가 성공한 뒤 표시한다. 실패하면 링크를 선택해서 복사할 수 있도록 안내한다.
- 방장은 waiting 상태에서만 설정을 수정한다. 로컬 선택은 저장 전 초안이고, 저장 실패 시 서버 값으로 복구한다. 설정 저장 중 시작 액션은 잠근다.
- 시작 가능 여부는 서버의 참여자 status와 응답을 기준으로 한다. 연결 끊김만으로 인원을 빼지 않는다. 인원 부족이면 “2명 이상 모이면 시작할 수 있어요”.
- `host:changed` 즉시 반영. 임시 위임/원래 방장 복귀는 서버 이벤트를 따른다. FE의 60초 타이머로 방장을 선출하지 않는다.
- 방 닫기는 방장 전용이며 “방을 닫으면 모두 나가게 돼요” 확인 후 요청한다. 성공 이벤트/응답 후 종료 안내로 이동한다.
- 게임 중 신규 입장의 대기실은 Q-2, 자발적 나가기 버튼은 Q-6 결정 전까지 확정 구현 대상에서 제외한다.

### 4.6 라운드 공개 — Countdown

근거: RD-02·03·08, EM-01·02. 참조: `Countdown.dc.html`.

- 해당 감정의 표시명·이모지·힌트, 현재/전체 라운드, 3→2→1을 표시한다. 일반적인 시작 장식만 있는 시안에 실제 감정 카드를 추가한다.
- countdownEndsAtMs까지 남은 시간을 표시한다. 지연 접속 시 3부터 다시 시작하지 않는다.
- 0 이후 장식 애니메이션이 촬영 시작을 늦추지 않는다. 이미 countdown이 지난 snapshot이면 촬영 화면으로 바로 이동한다.
- 숨겨진 다음 감정이나 전체 시퀀스를 FE에 내려받아 미리 표시하지 않는다.

### 4.7 촬영 — Play

근거: RD-03·08~10, CP-01~10, PM-04·11·13, PV-03. 참조: `Play.dc.html`.

- 좌상단 제출 인원/라운드 참여 인원, 우상단 타이머, 주제·힌트, 3:4 프리뷰 영역, 하단 셔터를 둔다. PRD §6.2의 “대기실 인원”보다 RD-09 및 BE activeCount가 우선하며 신규 대기자는 분모에 넣지 않는다.
- 촬영 준비 → 라이브 프리뷰 → 셔터 탭 → 사진 확인 → 다시 찍기/제출하기 순서다.
- 이미지 인코딩·업로드 중에는 이중 제출을 막는다. 서버의 202 또는 동등한 개인 제출 확인을 받은 뒤 결과 화면으로 전환한다. 단순 클릭·전송 시작·타인 제출 수 증가를 성공으로 취급하지 않는다.
- 10초 이하 타이머를 강조한다. 소리·진동·자동 제출·건너뛰기는 없다.
- 표시 타이머가 0이면 새로운 촬영/제출 입력을 잠그지만, 진행 중 업로드는 취소하지 않는다. 서버가 마감 전에 수신했다면 전송 완료가 늦어도 인정될 수 있다.
- 아직 제출 인정 여부를 모르면 “제출 확인 중” 상태를 표시하고 snapshot으로 확인한다. 로컬에서 0포인트·미제출을 확정하지 않는다.

### 4.8 라운드 결과 — RoundResult

근거: RS-01~09·11~15, RX-01~10, SC-01~06·09. 참조: `RoundResult.dc.html`.

- 상단 주제·내 점수/순위·집계 상태, 큰 사진 캐러셀, 가로 레일, 채점 현황, 감상 스킵 영역을 구성한다.
- 진입 직후 내 제출이 processing이면 “판별 중”. 아직 도착하지 않은 참여자 결과를 0점으로 추정하지 않는다.
- 열람자에게 허용된 모든 제출 사진을 캐러셀에 포함한다. 미제출자는 사진 없이 레일에만 표시한다. 사진이 있는 no_face·failed는 캐러셀·리액션 대상이다.
- `selectedParticipantId`로 현재 사진을 고정한다. 새 1위 도착·순위 변경은 레일 순서만 바꾸며 사용자가 보고 있는 사진을 바꾸지 않는다.
- 사용자 넘김/레일 탭은 현재 서버 순서에 따라 선택한다. 사진 1장이면 넘김은 비활성. 현재 사진이 제거되면 남은 허용 사진으로 이동하거나 빈 상태를 표시한다.
- 레일 순서는 서버 정렬값을 사용한다. FE가 점수 비교로 동점 순위를 결정하지 않는다. 필요한 전체 순위 갱신 계약은 B-2.
- 재정렬 애니메이션은 300~500ms, 기본 500ms. 연속 이벤트는 최신 목표 순서로 합쳐 순차 적용한다. 화면 종료 시 큐를 비운다. 애니메이션이 데이터 반영이나 다음 라운드를 지연시키지 않는다.
- 채점 현황은 서버 scoredCount/scoredTotal. 미제출 확정 이후에는 최종 결과 상태로 바꾸며 끝없이 `11/12 채점 중`에 머물지 않는다.
- targetScore는 `87.3점`처럼 소수점 한 자리. 순위 포인트는 `+100 포인트`로 점수와 단위를 구분한다. failed는 숫자 0으로 변환하지 않는다.
- 포인트는 round:finalized 이후에만 확정 표시한다. 중간 순위에 따라 포인트를 미리 부여하지 않는다.
- ♥는 “좋아요”, ⁇는 “판정이 궁금해요”로 접근성 이름을 부여한다. 시안의 “에계”, “이게 1등이라고?”는 사용하지 않는다.
- 내 사진, 채점 전, 라운드 닫힘, 재연결 중은 리액션을 비활성화하고 이유를 제공한다. 내 두 리액션 선택은 각각 독립적으로 복원해야 한다(B-3).
- 스킵은 감상 단계에서만 활성화한다. 일반 참여자는 “넘길 준비” 토글과 취소 안내. 방장은 “지금 다음 라운드로” 즉시 종료 액션임을 구분한다(Q-4).
- `viewingEndsAtMs` 도달 시 진행 확인 상태로 전환하고 서버 종료/다음 라운드 이벤트를 기다린다. FE가 다음 감정을 선택하지 않는다.

### 4.9 미제출 안내 — RoundMissed

근거: RS-11~15, RD-06. 참조: `RoundMissed.dc.html`, BE D-4.

- 이번 라운드를 놓쳤다는 사실과 다음 진행 대기만 표시한다. 사진·주제·점수·순위·리액션·스킵 현황은 store의 과거 값까지 포함해 노출하지 않는다.
- phase=scoring: “이번 라운드를 놓쳤어요 / 다음 라운드를 준비하고 있어요”. 확정되지 않은 12초 카운트다운을 만들지 않는다.
- phase=viewing: 서버 nextRoundAtMs 기준 남은 시간. 마지막 라운드는 “최종 결과를 준비하고 있어요” 및 “최종 결과까지”로 표시한다.
- 조기 스킵으로 예정 시각이 달라지면 새 라운드 이벤트를 즉시 반영한다. 상세 결과가 포함된 round:closed를 미제출자에게 보내는 방식으로 해결하지 않는다.
- 시안의 “이번 라운드 결과는 다음 라운드부터 함께 볼 수 있어요”는 삭제한다. 지난 라운드 결과가 나중에 공개되는 것처럼 안내하지 않는다.

### 4.10 최종 결과 — FinalRanking

근거: FN-01~04, RX-11, RO-13. 참조: `FinalRanking.dc.html`.

- 서버 ranking 순서대로 1~3위 시상대·전체 순위·totalPoints·누적 ♥/⁇를 표시한다. 2명 게임에서는 3위 자리를 생성하지 않는다.
- 본인 행을 표시하고 필요한 경우 해당 행으로 스크롤한다. 전체 순위 탐색을 막지 않는다.
- mostLoved는 별도 수상 블록. null이면 “이번 게임에는 좋아요 수상자가 없어요”. FE에서 수상자를 계산하거나 마지막 라운드 사진을 가져오지 않는다.
- 라운드 미제출자도 최종 결과는 볼 수 있다. 중단 종료는 서버 reason에 맞는 안내를 덧붙인다.
- 새 방 만들기 → 랜딩 방 설정. 방 나가기 → 미디어·store·소켓 정리 후 랜딩. 공유는 비활성 + 이유 문구.
- “셀카는 방을 나가면 삭제됩니다”는 Q-1의 최종 정책으로 교체한다. 최종 화면에 도달해서 사진을 새로 삭제하는 것으로 표현하지 않는다.

### 4.11 오류와 재연결 — ErrorStates

근거: RO-06·15, ID-05·07, PRD §6.5·7.2. 참조: `ErrorStates.dc.html`.

| 상태 | 처리 |
|---|---|
| 방 없음·종료 | 설명 + 새 방 만들기. 기존 참여자의 final 복원 가능 여부를 먼저 확인 |
| 정원 초과 | 방이 가득 찼어요 + 다시 확인하기. 자동 반복 입장 금지 |
| 일시적 단절 | 현재 진행 화면에 연결 복구 안내, 변경 액션 비활성, snapshot 복원 후 해제 |
| 10초 안에 복원되지 않음 | 수동 다시 연결·랜딩 이동 제공. 실패를 이유로 포인트 초기화 금지 |
| 세션 대체 | 다른 창에서 연결했어요. 자동 재연결 중지. 사용자가 선택한 재연결만 허용 |
| 점검·서버 오류 | 다시 시도. 서버가 주지 않은 종료 예정 시간은 표시하지 않음 |
| 방장 권한 변경 | NOT_HOST 응답 시 권한·화면 재조회, 사용자 입력을 성공 처리하지 않음 |
| 레이트 리밋 | 서버 재시도 시각/Retry-After가 있으면 표시. 연속 요청 잠금 |

## 5. 카메라와 이미지 수명

### 5.1 카메라 서비스

- MediaDevices로 전면 카메라 영상만 요청한다. 오디오 트랙은 요청하지 않는다. video는 모바일 인라인 재생을 전제로 한다.
- readyState·videoWidth·videoHeight 및 실제 프레임 준비를 확인한 뒤 셔터를 활성화한다.
- 촬영 화면 진입 후 1.5초까지 프레임이 없으면 로딩 안내, 3초까지 준비되지 않으면 재시도 버튼을 표시한다(CP-06). 시간 초과가 곧 영구 손실이라는 뜻은 아니다.
- 중복 카메라 초기화를 막고 요청 세대 번호로 늦게 도착한 스트림을 폐기한다. 화면을 떠난 뒤 resolve된 스트림도 반드시 stop한다.
- 권한 확인 후 대기실, 결과, 미제출, 최종, 방 종료에서는 track을 중지한다. 촬영 확인 단계는 재촬영에 필요한 동안만 스트림을 유지하고 제출 인정 시 정리한다.
- background→foreground에서 남은 라운드와 서버 제출 상태를 먼저 확인한다. 여전히 촬영 가능하면 프리뷰를 복구하고 실패 시 카메라 다시 켜기를 제공한다.
- 일시적인 mute/중단과 영구 종료·권한 철회를 구분한다. 모든 track ended를 사용자 권한 거부로 변환하지 않는다. 정책상 퇴장 처리는 Q-3 및 B-9와 연결한다.

### 5.2 캡처·인코딩

1. 셔터 탭 때 현재 video 프레임만 Canvas에 캡처한다.
2. 원본 프레임의 비율을 유지하고 `scale = min(1, 720 / max(width, height))`로 축소한다. 작은 이미지는 확대하지 않는다.
3. JPEG quality=0.8로 Blob을 만든다. null Blob·0 크기·비정상 MIME은 전송하지 않고 촬영 오류로 처리한다.
4. Blob URL로 촬영 확인 사진을 표시한다. 재촬영 시 이전 URL을 해제하고 Blob 참조를 버린다.
5. FormData의 image 필드로 전송한다. multipart boundary는 브라우저가 설정하도록 Content-Type을 직접 고정하지 않는다.

Q-7 확정(2026-09-08): 전면 프리뷰는 CSS로 좌우 반전하고, 촬영 시 전체 원본 프레임을 Canvas에서 한 번 좌우 반전해 JPEG로 인코딩한다. 생성된 Blob은 확인·제출·결과에 동일하게 사용하며 추가 반전하지 않는다. 3:4는 UI 프레임이다. 사진은 원본 비율을 유지한 채 object-fit: contain으로 전체를 표시하며 필요한 여백을 허용한다. 크롭하거나 늘여 맞추지 않는다. 서버도 결과용 이미지에 추가 반전·크롭을 적용하지 않는다.

### 5.3 미디어 폐기

| 자원 | 정리 시점 |
|---|---|
| 재촬영 이전 Blob·Object URL | 새 촬영 또는 촬영 취소 |
| 업로드 Blob | 제출이 확정되어 재전송이 필요 없어졌을 때. 확인 중이면 결과 판정까지 유지 |
| 타인 사진 Blob·Object URL | round:closed, round:voided, 다음 roundId, game:finished, 권한 상실, 방 종료 중 가장 이른 시점 |
| 모든 MediaStream | 해당 카메라 사용 화면 종료·권한 상실·방 종료 |
| 서명 URL·captureToken | 해당 라운드 종료·방 변경·권한 상실 |

이미지를 localStorage·sessionStorage·IndexedDB·Cache Storage에 저장하지 않는다. 미디어는 HTTP no-store, FE fetch도 no-store. 캐시용 Service Worker를 추가하지 않는다. URL·Blob·이미지 바이트·닉네임·초대 링크·토큰을 관측 로그에 넣지 않는다. 서버가 410 MEDIA_EXPIRED를 반환하면 사진 자리표시자와 이미 받은 텍스트 결과만 유지한다.

## 6. 시간·업로드·동기화

### 6.1 서버 시계

- 모든 wire timestamp는 epoch milliseconds, 이름은 `...AtMs`. 기기 Date.now만 신뢰하지 않는다.
- snapshot 요청 왕복 시간을 측정해 serverTimeMs로 시간 기준을 잡는다. 이후 performance.now의 경과량을 사용하며 foreground 복귀·재연결 때 다시 동기화한다.
- 남은 초는 `max(0, ceil((deadline - estimatedServerNow) / 1000))`. setInterval은 화면 갱신용이며 1초씩 값을 차감하는 게임 타이머가 아니다.
- 제출 마감·감상 종료 시각은 수정 없이 표시한다. 로딩·전화 수신·앱 전환 때문에 시간을 연장하지 않는다.
- 타이머 0 이후 상태가 계속 불명확하면 복원 요청과 복구 UI를 제공한다. 오래 걸린다는 이유만으로 FE가 라운드를 무효화하지 않는다.

### 6.2 업로드와 재시도

- `X-Capture-Token`을 담은 HTTP multipart 업로드. 서버 수신 시작 시각이 제출 인정 기준이다.
- 네트워크/일시 서버 오류만 자동 1회 재시도 대상. 응답 유실처럼 이미 접수됐을 수 있으면 snapshot 또는 제출 조회로 먼저 확인한다.
- 재시도 시 같은 이미지와 같은 논리 제출 식별자를 유지해야 한다. 현재 BE의 일회용 토큰·접수 슬롯 정책에는 충돌이 있어 B-4 해결 전 재전송 로직을 완료 처리하지 않는다.
- ALREADY_SUBMITTED는 반환된 기존 제출 상태를 복원한다. DEADLINE_PASSED는 재시도 버튼 없이 미제출 안내. NOT_CURRENT_ROUND는 최신 snapshot으로 이동한다.
- INVALID_CAPTURE_TOKEN은 무조건 다시 찍게 하지 않고 현재 라운드·기존 접수 여부부터 확인한다. PAYLOAD_TOO_LARGE/UNSUPPORTED_MEDIA는 동일 Blob 자동 재시도를 하지 않는다.
- 자동 재시도도 실패하면 수동 재시도 버튼. 단, 서버가 접수 가능함을 확인한 현재 라운드에만 제공한다.

### 6.3 재접속

1. 소켓 단절을 정상 오류 경로로 처리하고 변경 명령을 잠근다. 이미 진행 중인 HTTP 접수 여부는 별도로 확인한다.
2. 재연결 시 `/state`를 다시 받아 자신의 제출·점수·권한·마감·화면을 복원한다.
3. snapshot과 소켓 구독 사이의 이벤트 유실/역전을 막는 B-5 계약을 적용한다. 소켓 connected만으로 복원 완료를 선언하지 않는다.
4. roundId가 바뀌면 이전 라운드 이미지·명령·애니메이션 큐를 정리한다. 오래된 응답이 새 화면을 덮어쓰지 못하게 요청 generation을 검사한다.
5. session:superseded는 자동 복원 루프에서 제외한다. 이전 탭과 최신 탭이 서로 연결을 빼앗지 않게 한다.

## 8. 프로젝트 구조와 구현 경계

지정 스택: TypeScript, React, Vite, React Router, Zustand, TanStack Query, Socket.IO Client, Tailwind CSS, Motion. 구체적인 패키지 버전은 구현 착수 시 호환성을 확인해 lockfile에 고정한다.

```text
emoselfie-FE/
  src/
    app/                 # provider, router, screen resolver
    api/                 # HTTP client, DTO, error, snapshot adapter
    realtime/
      socket.ts
      handlers/          # room, round, submission, reaction, session
    stores/              # authoritative state replica, connection
    features/
      entry/             # landing, nickname, camera permission
      lobby/
      round/             # countdown, play, missed
      results/           # carousel, rail, final ranking
    camera/              # stream lifecycle, capture, encode
    media/               # URL ownership, authorized media loading
    components/          # shared UI
    styles/              # tokens, global styles
    tests/               # meaningful unit/integration scenarios
```

컴포넌트는 snapshot/event adapter를 통하지 않고 wire payload를 임의 해석하지 않는다. FE에는 점수·포인트·수상자 계산 모듈을 만들지 않는다. 샘플 셀카는 디자인 검수/테스트 fixture에만 쓰며 실제 카메라 실패를 숨기는 폴백으로 쓰지 않는다.

## 9. 현재 백엔드 연동 계약

### 9.1 HTTP

아래는 기존 BE 명세 §8의 계약이다. 누락된 응답 구조는 §10에서 보완한다.

| 메서드/경로 | FE 사용 |
|---|---|
| GET /api/me | 쿠키 세션 준비·닉네임 기본값·활성 소유 방 힌트 |
| PATCH /api/me | 닉네임 저장 |
| POST /api/rooms | 설정으로 생성, existing이면 기존 방 복원 |
| GET /api/rooms/{slug} | 신규 입장 전 존재·입장 가능성 확인 |
| POST /api/rooms/{slug}/participants | 카메라 확인 후 등록/재입장 |
| GET /api/rooms/{slug}/state | 현재 화면·내 제출·마감·결과 복원 |
| PATCH /api/rooms/{slug}/settings | 대기실 설정 저장 |
| POST /api/rooms/{slug}/start | 방장 시작 |
| POST /api/rooms/{slug}/close | 방장 방 닫기 |
| DELETE /api/rooms/{slug}/participants/me | 자발적 퇴장. UI 노출 범위는 Q-6 |
| POST /api/rooms/{slug}/rounds/{roundId}/submissions | image + X-Capture-Token |
| GET /media/{mediaToken} | 열람자 전용 결과 사진. 410이면 자리표시자 |

실패 응답은 `{error:{code,message,detail}}`. code로 동작을 분기하고 message는 텍스트로 표시한다. UUID를 body·query·소켓 auth에 복사하지 않는다.

### 9.2 실시간 이벤트

| 이벤트 | 적용 |
|---|---|
| room:joined | 연결 후 참여자·방 설정 초기화. snapshot과 버전 조정 필요 |
| room:settingsUpdated | 서버 설정 대입 |
| participant:updated / participant:removed | 연결/참여 상태 갱신, 본인 퇴장 시 접근 차단 |
| host:changed | 서버 지정 방장·임시 위임 상태 갱신 |
| room:closed | 종료 사유 표시·미디어 정리·소켓 해제 |
| game:started | 게임 설정과 participantIds 갱신 |
| round:revealed | 감정·countdownEndsAtMs·deadlineAtMs·captureToken·activeCount 갱신 |
| submission:status | 제출 현황만 갱신. 누가 제출했는지 추정 금지 |

C→S는 reaction:sent, round:skip, permission:changed, presence:ping. presence:ping은 BE에 명시된 25초 주기를 따르되 FE 타이머가 background에서도 정확히 실행된다고 가정하지 않는다. 연결 복귀 시 snapshot을 갱신한다. PRD의 submission:uploaded 이미지 소켓 전송은 FE/BE 가이드의 HTTP 방식으로 대체한다.

## 10. 백엔드 계약 보완 — 연동 완료 전 필수

아래는 **현재 API에 존재한다고 가정하면 안 되는 항목**이다. 제품 결정을 FE가 대신 내리지 않고, 기존 백엔드 명세의 개정 또는 공동 DTO 계약으로 해결한다.

| ID | 현재 계약의 문제 | 필요한 계약 |
|---|---|---|
| B-1 | snapshot 예시는 capture만 완전함. result/final/missed의 필수 필드·game=null인 lobby screen 위치 불명 | screen별 discriminated union, 결과 목록·미디어 토큰·내 선택·감상 마감·최종 순위의 필수/nullable 정의 |
| B-2 | submission:scored는 새 결과의 currentRank만 제공. 기존 사람의 순위가 밀리는데 FE 순위 계산은 금지. submission:status도 총수뿐이라 다른 사람의 processing 슬롯 식별 불가 | 열람자 전용 전체 orderedParticipantIds/rank 목록 및 개인별 pending/processing 상태. 촬영자에게는 기존처럼 집계 수만 제공 |

| B-7 | PM-07은 권한 전 방 정보 비공개인데 BE §6.4는 최소 3필드, §8.2는 status·settings·isHost까지 반환 | 권한 전 허용되는 최소 응답 확정. FE가 숨기는 것과 서버가 보내지 않는 것은 별도 문제. Q-2 결과도 반영 |

| B-10 | 신규 입장자 추가 이벤트 없음, 12색 colorTag 팔레트 미정, 설정·시작·종료 HTTP 응답 불완전 | participant 추가/전체 목록 갱신 이벤트, FE 12색 매핑, HTTP mutation 응답 DTO |

기술 보완안은 BE와 합의된 후에만 실제 필드·이벤트명으로 고정한다. 예를 들어 revision을 FE가 임의 생성해 서버 최신성 보장으로 사용하지 않는다. Q-2의 신규 입장 규칙을 바꾸면 기존 BE waiting_next_game 계약도 함께 개정해야 한다.

### 11.2 모바일·성능

- iOS Safari 최신 2개 버전, Android Chrome 최신 2개 버전에서 실제 기기로 권한·촬영·업로드·전화/앱 전환·화면 잠금·회전·소켓 복원을 검증한다. 데스크톱 mock 통과만으로 완료 처리하지 않는다.
- 단위 테스트는 타이머 오차 보정, snapshot/event 역전, 리액션 재시도, 캡처 비율·자원 정리 등 실패 위험이 있는 로직에 집중한다. 정적 문구·단순 스타일을 복제하는 테스트는 만들지 않는다.
- 통합 테스트는 서버가 허용하지 않은 데이터가 전달되지 않는 것까지 확인한다. display:none 검증으로 접근제어 테스트를 대체하지 않는다.
- PRD 목표: 4G에서 초대 링크→대기실 렌더 p95 2초, 업로드 완료→결과 p95 3초, 클라이언트 간 라운드 전환 편차 500ms 이내.
- 링크→대기실에는 닉네임 입력·권한 팝업 대기라는 사용자 시간이 있으므로 기술 렌더 시간과 사용자 대기를 나눠 측정한다. PRD 지표 정의의 보완이 필요하며 수동 입력 시간 포함 여부를 임의로 숨기지 않는다.
- 초기 화면에 필요 없는 결과·애니메이션 코드는 지연 로딩한다. 카메라 진입 지연과 번들 크기는 실제 모바일에서 측정한다.
- 계측 이벤트는 입장 단계, 권한 결과, 카메라 준비 시간, 업로드/채점 지연, 재접속 소요, 최종 화면 도달을 다룬다. 외부 분석 서비스·사용자 식별 전송은 이 명세에서 추가하지 않는다.

## 12. 구현 순서와 완료 조건

1. 공통 토큰·AppShell·오류/폼 컴포넌트와 서버 adapter의 타입 경계를 만든다.
2. 세션·방 생성·닉네임·카메라 안내·권한 거부·대기실을 연결한다.
3. 실제 모바일 카메라 캡처/압축/제출을 검증한다. 모의 점수는 테스트 환경에만 둔다.
4. 카운트다운·업로드 인정·실시간 결과·리액션·스킵을 연결한다.
5. 미제출·무효·중단·최종 결과와 방장/연결 복원을 구현한다.
6. §11의 모바일·접근제어·시간·자원 해제 검증을 수행한다.

문서 확정 조건은 Q-1~Q-7의 결과 기록, B-1~B-12의 계약 합의, 변경된 PRD/BE 조항과 이 문서의 연결이다. 그 전에도 공통 UI와 확정된 정상 흐름은 구현할 수 있으나, 미확정 분기를 임의 구현해 완료 처리하지 않는다.

프론트엔드 완료 조건은 P0 요구사항 연결, 서버 권위 유지, 실제 모바일 검증, 재접속 복원, 이미지 비영구 저장·폐기 검증, 결정 대기 분기 해소다.
