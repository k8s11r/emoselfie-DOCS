## 1. 토큰 정본은 v2

`Design Tokens.dc.html`(v1)과 `Design Tokens v2.dc.html`은 **서로 다른 디자인 방향**이다.

```
v1   "밝지만 놀리지 않는 톤"      oklch 색상환 기반. L·C 고정, hue만 회전
v2   "스티커 팝 / 아기자기"       로고 계승. 3px 검정 외곽선 + 하드 섀도
```

**v2를 정본으로 한다.** 근거 셋:

| 근거 | 내용 |
|---|---|
| 색 | v2의 hex가 PRD 5.4와 정확히 일치한다. v1은 oklch 상대값이라 대응 자체가 불가능하다 |
| 문구 | v2에 `"뒤에서 누가 부른 것처럼"` 이 있다. PRD EM-02가 인용한 바로 그 문장이다 |
| 수치 | v2는 `00:20` · `12명 중 7명`. v1은 `00:09` · `4명 중 3명` |

`Design Tokens.dc.html`(v1)은 참조 대상에서 제외한다.

## 2. 감정 7종 — 색은 그대로, 이름표만 옮긴다

C-1은 팔레트를 바꾸지 않았다. **설렘·당황 두 칸의 이름과 이모지만 우웩·무서움으로 교체됐다.**

| 색 | v2 시안 | → | PRD v1.1 | 엔진 라벨 |
|---|---|---|---|---|
| `#FFD72F` | 😆 기쁨 | = | 😆 기쁨 | `Happiness` |
| `#FF5A47` | 😠 분노 | = | 😠 분노 | `Anger` |
| `#8F66FF` | 😲 놀람 | = | 😲 놀람 | `Surprise` |
| `#5AC8FF` | 😢 슬픔 | = | 😢 슬픔 | `Sadness` |
| `#80EFD6` | 😐 시크 | = | 😐 시크 | `Neutral` |
| `#FF3D86` | 🥰 **설렘** | **→** | 😨 **무서움** | `Fear` |
| `#B8F16A` | 😳 **당황** | **→** | 🤢 **우웩** | `Disgust` |

`#FF3D86`은 브랜드 primary(pink)와 같은 색이다. 무서움 라운드에서 감정색과 브랜드색이 겹치는데, v2의 "화면당 감정색 1종" 규칙이 있으므로 그 화면에서는 primary 버튼을 ink로 쓰는 등의 조정이 필요하다. **확인 대상.**

### 신규 작성 필요 — 한 줄 설명 (EM-02)

우웩·무서움은 v2에 설명 문구가 없다. 놀람의 `"뒤에서 누가 부른 것처럼"` 톤으로 새로 쓴다.

```
🤢 우웩     (신규)
😨 무서움   (신규)
```

나머지 5종의 설명도 시안에 다 있지는 않다. 서버가 `round:revealed`로 내려주는 값이므로 (EM-02) **7종 전부 확정 필요**하다.

// ❌ C-4: 증가 카운터

// ✅ 토글

## 6. 시안 갱신 방법

`.dc.html`은 Claude Design 캔버스 파일이다 (`<x-dc>` + dc-runtime `support.js`).

2026-09-04 시점 이 계정에 **게시된 아티팩트가 없다.** 이어서 편집하려면 로컬 파일을 씨앗으로 캔버스를 다시 만들어야 한다.

```
로컬 .dc.html  →  design 스킬로 re-seed  →  캔버스 Artifact 게시
                                          →  클릭 선택 · 속성 패널 · 인라인 편집
                                          →  Save 시 새 버전 게시
```

- 로컬 `support.js`는 로컬 실행용이며 게시본에는 호스팅 런타임이 쓰인다.
- 원래 캔버스를 다른 계정에서 만들었다면, 그 링크로 기존 아티팩트를 직접 업데이트하는 편이 버전 이력이 이어져 낫다.
